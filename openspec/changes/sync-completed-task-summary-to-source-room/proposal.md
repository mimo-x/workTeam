## Why

Task 从普通群进入独立 Task 小群后，最终内容和状态不会在人工验收完成时形成来源群中的持久消息，群成员必须主动进入 Task 小群才能知道结果。这破坏了“大家在一个群里工作”的闭环。

## What Changes

- 保存 Agent 的结构化完成摘要，并在父子 Task 间确定性汇总摘要和产物。
- 仅在根 Task 首次被管理员验收为 `done` 后，向来源群发布一条持久结果消息。
- 本地模式直接写入来源群；云端模式使用现有事务 Outbox 投递到来源 OpenIM 群。
- 为结果消息携带 Task 和产物元数据，并在桌面端展示紧凑的完成结果卡。
- 对重复验收、历史已完成 Task 和子 Task 保持不重复、不补发、不刷屏。

## Capabilities

### Modified Capabilities

- `agent-task-delegation`: 将来源群结果发布时机调整为根 Task 人工验收完成，并定义本地/云端的一致持久化行为。

## Impact

- 增加向后兼容的 Task 完成摘要与发布时间字段。
- 扩展房间消息 DTO 和桌面消息快照的结果消息元数据。
- 不增加新的模型调用，不改变现有 Task 状态接口的请求格式。
