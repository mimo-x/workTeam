# Task 验收完成后未向来源群同步总结

## 现象

用户从群聊创建并执行 Task 后，Task 结果只出现在 Task 小群或状态事件中。管理员完成验收后，来源群没有一条可回看、可定位原 Task 的结果总结。

## 复现 Case

Given 一个根 Task 从普通群创建，Agent 已在 Task 小群提交完成摘要和产物
When 群管理员将根 Task 人工验收为 `done`
Then 来源群应新增且只新增一条包含 Task 标题、完成摘要、产物和 Task 关联信息的结果消息

实际结果：来源群没有结果消息。本地模式只更新 Task 状态；云端模式只向 Task 小群投递 Agent 最终内容，来源群收到的状态事件不会形成持久消息。

## 环境与请求信息

- 客户端：macOS Electron
- 群 ID：`local-agent-team`
- 用户请求：`@审查员 读取一下你桌面上的文件`
- Agent：审查员（Reviewer）
- Provider：Codex
- UI 所选模型：`gpt-5.6-luna`
- Session ID：截图未显示
- Run ID：截图未显示
- Task：`读取桌面文件`
- 截图中的独立原始错误：`Error invoking remote method 'backend:request': Error: 聊天后台返回 HTTP 404`

HTTP 404 不作为本 Bug 的推定根因，也不纳入本次修复范围。

## 预期结果

- 仅根 Task 在管理员首次验收为 `done` 后同步。
- 子 Task 只向父 Task 汇总，不直接刷来源群。
- 总结来自已有结构化完成摘要、Agent 最终输出和子 Task 摘要，不额外调用模型。
- 重复验收或投递重试不得在应用数据中生成重复总结。

## 根因

本地编排在人工验收时只更新 Task 状态，没有创建来源群消息。云端编排将 Agent 最终内容通过 Outbox 发送到 Task 小群；父子汇总虽然向来源群广播 `task.children-aggregated`，但该瞬时事件不会写入 OpenIM 或消息镜像。两条路径都没有“根 Task 验收完成后发布持久总结”的实现。

失败基线：新增本地 BDD Case 后来源群总结数量为 `0 !== 1`；后端集成 Case 中 `task_source_summary` Outbox 数量同样为 `0 !== 1`。

## 修复与验证

### 修复

- 本地和云端 Task 都会保存结构化 `complete` 摘要；缺失结构化动作时使用已有 Agent 最终输出，不增加模型调用。
- 子 Task 只聚合到父 Task；根 Task 首次由群主或管理员标记 `done` 时，才向来源群发布一条持久总结。
- 云端在状态事务内同时写入发布时间和 Outbox，复用稳定 operation ID，并通过 delivery key 防止投递重试形成重复消息镜像。
- 来源群正文和产物元数据都会移除凭据与主机绝对路径；消息 API 只解析 `kind`、`taskId` 和 `artifactRefs` 白名单。
- 来源群以现有 shadcn/Base UI 的 Card、Badge 和 Button 展示紧凑结果卡，并同步更新设计系统示例与规则。
