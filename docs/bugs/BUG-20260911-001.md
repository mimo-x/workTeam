# 本地群保存云端 Agent 时提交了无效房间路径

## 现象

用户在已存在的本地群中管理成员并保存时，桌面端显示
`Error invoking remote method 'backend:request': Error: 路径参数不正确。`，群成员没有保存。

## 复现 Case

Given 桌面端已登录云端，当前房间是本地群 `local-agent-team`，且已选 Agent 带有 `cloudAgentId`
When 用户打开群成员管理并点击“保存群组”
Then 保存逻辑向后台发送 `PUT /v1/rooms/local-agent-team/members`，后台因 `:id` 不是 UUID 返回“路径参数不正确。”

## 预期结果

已有本地群 SHALL 始终走本地更新，不得把本地 `roomId` 拼入云端房间 API。已有云端群仍走云端更新；新建群只有在云端模式且包含云端成员时才走云端创建。

## 实际结果

保存目标仅根据云端模式和成员是否带云端身份判断。已有本地群中的已发布 Agent 满足该条件，使本地群被误判为云端群。

## 环境

- macOS Electron 桌面端
- 工作区：`/Users/mvbj0705/dev/agent-team`
- 本地持久化房间：`roomId=local-agent-team`、`syncSource=local`
- 已选 Agent：本地 Agent，带 UUID 格式的 `cloudAgentId`

## 原始日志

```text
Error invoking remote method 'backend:request': Error: 路径参数不正确。
```

## 根因

`RoomDialog.save` 使用 `room?.syncSource === "backend" || (cloudMode && remoteSelection)` 决定保存目标。该表达式没有区分“新建群”和“已有本地群”；已有本地群只要包含已绑定云端身份的 Agent，就会进入云端更新分支，并将 `local-agent-team` 作为后端 UUID 路径参数。

## 修复说明

提取可测试的 `resolveRoomSaveTarget` 决策函数。已有房间优先依据自身同步来源选择保存通道：仅 `syncSource=backend` 走云端更新，本地或旧数据中未显式标记来源的房间均走本地更新；只有新建房间才依据云端模式与远端成员选择决定是否创建云端群。`RoomDialog` 已改为调用该共享规则。
