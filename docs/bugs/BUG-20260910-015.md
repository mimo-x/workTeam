# 云端保存 Agent 只显示笼统的 400 参数错误

## 复现 Case

Given 用户已登录聊天后台并在桌面端打开 Agent 设置
When 用户点击“保存 Agent”
Then 云端 `POST /v1/agents` 成功，或界面显示具体字段校验原因

## 实际日志

```text
Error occurred in handler for 'backend:request': BackendHttpError: 请求参数不正确。
statusCode: 400
code: VALIDATION_ERROR
```

同时出现的 `IMKCFRunLoopWakeUpReliable` 是 macOS 输入法窗口日志，不是本次后台 400 的根因。

## 环境与根因

桌面端 Electron 云端模式。后台 `parseBody` 会把 Zod 的字段级 `details` 放进响应，但 `BackendClient.rawRequest` 只读取 `error.code` 和 `error.message`，因此具体失败字段被丢弃。此前 BDD 只覆盖本地 `AgentTeamService.saveAgents`，没有覆盖云端 `POST /v1/agents`。

从后台 schema 可知，常见触发条件包括 mention 格式不符合 `@中文/字母/数字/_/-` 规则，以及远程 Runtime endpoint 不是 HTTPS 或允许的本地地址；仅凭原始日志无法断定本次具体字段，因为详情已被客户端丢弃。

## 修复说明

云端保存前增加桌面端字段校验，并保留后台字段级校验详情；新增 BDD 覆盖默认 payload、非法 mention、非法 endpoint 和错误详情格式化。

## 验证结果

70 个桌面测试、后端 5 个测试、Lint、类型检查、构建和 Bug 门禁通过。真实后台 Electron 手动复核仍需在用户的后台环境执行。
