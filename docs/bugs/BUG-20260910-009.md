# 桌面端群聊发送使用容器内 OpenIM 地址

## 现象

好友私聊可以发送，但群聊中 @ 好友后发送失败。桌面端从 `/v1/im/session` 获取到的 `apiAddr` 是容器内 hostname，桌面进程无法解析。

## 复现 Case

Given 桌面端已登录并连接 OpenIM，群聊已包含好友
When 用户发送一条 @ 好友的群聊消息
Then 消息应通过公开 OpenIM API 发送并显示在群聊中

实际结果：页面显示 `lookup openim-server: no such host`，消息发送失败。

## 环境与原始错误

- 客户端：macOS Electron 开发模式
- 服务端：Docker Compose 部署
- `/v1/im/session` 返回的 `apiAddr`：`http://openim-server:10002`
- 原始错误：`Error: 10000 Network error ... dial tcp: lookup openim-server: no such host`

## 根因

`OPENIM_API_URL` 同时承担服务端访问地址和返回给桌面端的地址。部署脚本将其设置为 Docker 网络内的 `openim-server`，桌面端无法使用该地址。

## 修复与验证

增加独立的 `OPENIM_PUBLIC_API_URL` 配置：服务端继续使用内部地址，桌面端会话配置返回公开地址。修改服务端配置后需要重新执行 `bash deploy.sh`，再进行群聊 UI 验收。
