# Agent 云端 ID 校验失败并触发 OpenIM 原生崩溃

## 复现 Case

### 云端 Agent 请求

Given 桌面端存在本地 Agent `agent_coder`，或已有历史 Agent 映射的 `cloudAgentId` 不是 UUID
When 用户在已登录后台的桌面端保存 Agent、删除 Agent、创建 Agent 私聊或把 Agent 加入云端群
Then 桌面端只能使用有效 UUID 调用后台 Agent 路径和群成员接口；本地 Agent 应先创建云端记录

实际结果：桌面端把 `agent_coder` 作为 `/v1/agents/:id` 的路径参数，后台返回 `400 VALIDATION_ERROR` 和 `路径参数不正确。 id: Invalid UUID`。

### OpenIM 原生回调

Given macOS arm64 桌面端使用 `@openim/electron-client-sdk` 连接 OpenIM
When OpenIM 收到 `OnKickedOffline` 事件
Then Electron 进程应保持运行并把连接状态更新为错误

实际结果：进程在 cgo 回调 `main.ConnCallback.OnKickedOffline` 中出现 `SIGSEGV: segmentation violation`，无法继续操作。

## 环境与原始错误

- 日期：2026-09-10
- 平台：macOS arm64，Electron 开发模式
- Electron SDK：`@openim/electron-client-sdk` `3.8.3-patch.15.1`
- 后台错误：

```text
BackendHttpError: 路径参数不正确。 id: Invalid UUID
statusCode: 400
code: VALIDATION_ERROR
```

- 原生错误：

```text
SIGSEGV: segmentation violation
main._Cfunc_Call_CB_I_S(...)
main.ConnCallback.OnKickedOffline(...)
```

- `error messaging the mach port for IMKCFRunLoopWakeUpReliable` 是 macOS 输入法日志，与上述两个问题没有因果关系。

## 初步根因

后台 `services/chat-api/src/agents.ts` 使用 `z.string().uuid()` 校验 Agent 路径参数。桌面端 Agent 记录同时存在本地稳定 ID、云端 UUID 和 OpenIM 用户 ID，但保存、私聊和群成员流程没有统一检查 `cloudAgentId`，导致本地 ID 被误用为后台路径参数。

`SIGSEGV` 发生在 OpenIM 原生 SDK 的 Go/cgo 回调边界，堆栈落在 `OnKickedOffline` 和 `Call_CB_I_S`。现有桌面端只在退出时释放 Electron SDK 包装器，没有在 renderer 生命周期变化和后台账号切换时保证 `logout -> unInitSDK` 顺序，因此需要先补生命周期串行化和关闭清理；若仍可复现，应继续向 OpenIM SDK 上游提交原始 arm64 崩溃堆栈。

## 修复目标

- 所有后台 Agent 路径和 `agentIds` 请求只接受有效 UUID。
- 本地 Agent 在云端群流程中自动走 `POST /v1/agents` 晋级，不把本地 ID 放入云端请求。
- 历史无效云端映射不再触发 DELETE/PATCH/私聊请求。
- OpenIM 连接切换、账号退出和 renderer 卸载统一串行执行 `logout -> unInitSDK`，避免旧连接继续回调。
- 保留原始 native SDK 版本和 arm64 崩溃证据，自动化 Case 不宣称能够替代真实 native 复现。
