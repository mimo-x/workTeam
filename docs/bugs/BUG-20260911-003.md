# 亮色主题下新建消息群弹窗仍显示暗色

## 现象

用户在亮色主题的消息页面点击“新建群组”后，页面外壳保持亮色，但新建群组弹窗的容器、输入框和成员卡片仍显示为暗色，正文对比度也按暗色主题渲染。

## 复现 Case

Given 桌面端已选择亮色主题并进入消息页面
When 用户点击消息列表顶部的“新建群组”按钮
Then 新建群组弹窗应使用亮色主题的弹窗、输入、成员选择和文字语义色

## 预期结果

新建及管理群组弹窗 SHALL 继承应用当前主题，在亮色和暗色主题下均使用设计系统语义 token，并保持现有群名称、Agent 成员和好友成员选择行为。

## 实际结果

弹窗内容在亮色主题下仍使用固定暗色背景、半透明黑色输入与成员卡片、白色边框和 zinc 文字色。

## 环境

- macOS Electron 桌面端
- 工作区：`/Users/mvbj0705/dev/agent-team`
- 外观：亮色主题
- 页面：消息 > 新建群组

## 原始日志

```text
无运行时错误；视觉错误表现为亮色应用外壳中的新建群组弹窗仍为暗色。
```

## 根因

`RoomDialog` 未包含在此前消息主界面的主题迁移范围内，仍使用自定义 `Modal` 和固定 `#11151e`、black、white、zinc、cyan、emerald、red 色阶。亮色主题只更新设计系统 CSS 变量，无法覆盖这些直接写入组件的颜色声明。

## 修复说明

将 `RoomDialog` 迁移到仓库已有的 Base Nova `Dialog`、`Input`、`Label` 和 `Button` 组件。弹窗表面、边框、正文、说明、选中状态和错误提示全部改用设计系统语义 token；成员区改为带可访问名称和 `aria-pressed` 状态的选择控件，并为长列表增加弹窗内滚动。群组保存与成员选择的数据逻辑未改动。

## 验证结果

- 修复前新增 BDD Case 失败，并命中 `RoomDialog` 中的固定暗色声明；修复后通过。
- `npm run test:desktop`：91/91 通过。
- `npm run lint`、`npm run typecheck`、`npm run build`：通过。
- `npm run validate:bugs`：16 个 Bug 记录通过。
- 用户在亮色主题下实际查看新建群组弹窗，确认问题已解决；暗色主题由同一组语义 token 和双主题回归 Case 覆盖。
