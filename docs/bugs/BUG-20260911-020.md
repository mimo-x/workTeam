# 群成员无法与其他成员拥有的 Agent 对话

## 现象

同一后台同步群中，Agent 所有者可以 `@` 自己的本机 Agent 并在本地看到回复；其他群成员 `@` 该 Agent 时不会触发回复。Agent 已生成的回复还可能只出现在所有者本地，其他群成员不可见。

## 复现 Case

Given 用户 Alice 和 Bob 已注册并加入同一个后台同步群，群内包含 Alice 拥有且在线的本机 Agent
When Bob 在群里发送一条明确 `@` Alice Agent 的普通聊天消息
Then Alice 当前唯一托管该 Agent 的桌面应收到精确聊天请求、以只读聊天权限执行一次，并将回复持久发布到原群，使 Alice 和 Bob 都能看到

实际结果：Bob 的消息只进入群时间线，没有路由到 Alice 的 Agent Host；Alice 本地生成的 Agent 回复向当前后台调用发布接口时返回 HTTP 404。

## 环境与原始证据

- 客户端：macOS Electron
- 工作区：`/Users/mvbj0705/dev/agent-team`
- 用户消息：`@程序员 今天几号？`
- Agent：程序员（Coder）
- 原始错误：`OpenIM 发布失败：聊天后台返回 HTTP 404`
- 接口探测：`POST /v1/rooms/67aa59ad-e315-4f2f-b3f6-63f3216a863f/agent-messages` 返回 `404 Route ... not found`
- Session / Run：好友消息没有创建；所有者消息可创建但截图未展示具体 ID
- Provider / Model：好友消息未进入 Runtime；所有者消息使用当前桌面所选 Provider / Model

## 预期权限边界

- 只有经过鉴权的 OpenIM 回调、已在群中的 Human、已加入该群的 Agent 才能形成跨用户聊天请求。
- 请求只发送给 Agent 所有者当前托管该 Agent 的一个在线 Host，且目标 Agent ID 由服务端解析的 `@` 列表决定，客户端正文不得扩大目标。
- 普通跨用户聊天沿用非 Task 的只读 Session，不开放工作区写入、命令执行或权限提升；需要操作电脑的请求仍必须转为受治理 Task。
- Agent 回复继续通过所有者登录态和幂等 delivery ID 发布，其他成员不能伪造 Agent 身份。

## 根因

存在两个相互独立的问题：

1. 后台同步群的 OpenIM 入站监听明确以 `!mappedRoom?.syncSource` 为条件，只允许本地群触发 Agent；OpenIM after-message 回调虽然已经校验群成员并解析、持久化精确的 `target_agent_ids`，但只广播 `message.mirrored` 刷新事件，没有把聊天请求定向交给 Agent 所有者的 Host。因此所有者本人发送时可以走本地发送分支，Bob 等其他成员发送时没有 Runtime 调度入口。
2. 运行中的 Docker API/Worker 镜像落后于源码，缺少源码已实现的 `POST /v1/rooms/:id/agent-messages` 路由。修复前对房间 `67aa59ad-e315-4f2f-b3f6-63f3216a863f` 探测返回 `404 Route ... not found`，导致所有者本地生成的回复无法进入 OpenIM Outbox 和共享群消息流。

修复增加了 `agent.chat.requested` 定向事件：服务端只对 Human 的普通群聊发送，按 Agent 所有者和 Host 注册的 Agent 集合选择最近注册的一个在线连接；桌面主进程同步后台快照后，再次限制为自有、本机执行的精确目标，并调用现有外部消息调度。非 Task 消息仍由既有 Runtime 规则强制使用 `read-only` Session。Agent 回复继续复用带所有权、群成员关系、Agent 入群和 delivery ID 幂等校验的发布接口。
